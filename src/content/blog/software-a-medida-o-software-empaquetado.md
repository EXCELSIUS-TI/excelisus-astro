«¿Compramos un sistema o lo desarrollamos?» Es una de las decisiones tecnológicas más caras de revertir. Elegir mal significa años pagando licencias por funciones que nadie usa, o años manteniendo un desarrollo propio para algo que un producto resolvía mejor.

No hay una respuesta universal, pero sí criterios claros.

## Las dos opciones

- **Software empaquetado**: un producto existente —un ERP, un CRM, un sistema de planillas— que se configura y, a veces, se personaliza. Pagas licencias o suscripción.
- **Software a medida**: un sistema desarrollado para tus procesos. Pagas el desarrollo y el mantenimiento, y el sistema se adapta a la empresa, no al revés.

## Comparación directa

| Criterio | Empaquetado | A medida |
| --- | --- | --- |
| Tiempo hasta usarlo | Semanas | Meses, por fases |
| Inversión inicial | Baja o media | Media o alta |
| Costo recurrente | Licencias por usuario | Mantenimiento y hosting |
| Encaje con el proceso | La empresa se adapta | El sistema se adapta |
| Integraciones | Las que el producto permita | Las que necesites |
| Dependencia del proveedor | Alta | Baja, si eres dueño del código |
| Ventaja competitiva | Ninguna: tu competencia usa lo mismo | Posible, si el proceso te diferencia |

## Cinco preguntas para decidir

### 1. ¿El proceso te diferencia?

Si la contabilidad o las planillas funcionan igual en todas las empresas del rubro, un producto estándar es la opción sensata. Si tu forma de cotizar, despachar o atender es parte de lo que te hace competitivo, **forzarla a un software genérico es perder esa ventaja**.

### 2. ¿Cuántas integraciones necesitas?

Si el sistema tiene que conversar con tu ERP, tu facturador electrónico, una app de reparto y una plataforma de pagos, revisa cuánto cuesta integrar cada pieza en el producto empaquetado. A veces las integraciones cuestan más que el sistema.

### 3. ¿Cómo crece el costo con los usuarios?

Las licencias por usuario parecen baratas con diez personas y dejan de serlo con doscientas. Proyecta el **costo total a tres o cinco años**, no solo el primer pago.

### 4. ¿Qué pasa si el proveedor desaparece o sube el precio?

Con software empaquetado dependes de su hoja de ruta y de sus precios. Con software a medida, la dependencia se controla si el contrato establece que **el código y la documentación son tuyos**.

### 5. ¿Tienes tiempo para un desarrollo?

Si necesitas operar el mes que viene, un producto existente gana. Un desarrollo serio se entrega por fases y toma meses, aunque cada fase ya aporte valor.

## La opción que casi siempre gana: híbrida

En la práctica, la mayoría de empresas termina con una combinación: un **ERP para los procesos estándar** —compras, inventario, contabilidad, facturación— y **desarrollos a medida donde el negocio es distinto**, conectados por API.

## Señales de alerta al contratar un desarrollo

- El presupuesto no detalla **qué entra y qué no**.
- No hay entregas intermedias con algo funcionando.
- El contrato no dice **de quién es el código**.
- No se habla de pruebas, documentación ni ambiente de pruebas.
- Nadie pregunta por el proceso real antes de proponer una solución.
